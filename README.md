# BLEVE Pressure Prediction

Machine learning prediction of peak pressure generated by **Boiling Liquid Expanding Vapour Explosion (BLEVE)** scenarios using event-aware preprocessing, physics-inspired feature engineering, and ensemble regression.

## Results

- **4th place** on the public leaderboard
- **10th out of 448 entries** on the final leaderboard
- Best public leaderboard MAPE: **0.13285**
- Local validation MAPE: **0.12622**
- Local validation R²: **0.96276**

The final ensemble achieved substantially lower prediction error than the individual Ridge Regression, Random Forest, and neural-network baselines.

| Model | Validation MAPE | Kaggle Public MAPE |
|---|---:|---:|
| Ridge Regression | 0.7421 | 0.7037 |
| Random Forest | 0.2393 | 0.2536 |
| Neural Network | 0.1743 | 0.1737 |
| **Final Ensemble** | **0.1262** | **0.13285** |

## Project Overview

This project predicts peak pressure around an obstacle following a BLEVE using physical setup parameters and sensor measurements.

A key characteristic of the dataset is that each BLEVE scenario contains up to **27 related sensor readings**. Rather than treating every row as an independent observation, the modelling pipeline identifies complete BLEVE events and uses this structure during data cleaning, preprocessing, feature engineering, and validation.

The overall workflow consists of:

- data auditing and cleaning
- 27-sensor BLEVE event identification
- event-level denoising
- physics-inspired feature engineering
- categorical and sensor-position encoding
- feature scaling
- Box-Cox and log target transformations
- event-based hold-out validation
- baseline model comparison
- multi-branch ensemble modelling
- validation-based calibration
- final test-set prediction

## Data Processing

The raw data required several preprocessing steps before model development. These included removing rows with missing target values, duplicate-row removal, detection of incomplete training events, correction of inconsistent categorical values, unit checks, event-level denoising, and robust handling of extreme observations.

Rows belonging to the same BLEVE event share common physical conditions. Event-level information was therefore used to improve consistency while keeping sensor-specific measurements such as sensor location and target pressure unchanged.

## Feature Engineering

The preprocessing pipeline expands the raw physical variables into **154 numeric features** covering:

- tank and obstacle geometry
- sensor distance
- scaled-distance and inverse-distance proxies
- thermodynamic conditions
- liquid and vapour state
- reduced pressure and temperature measures
- obstacle interaction effects
- sensor position and orientation
- sensor-side indicators
- repeated sensor-position patterns
- nonlinear interaction terms

A smaller physics-focused feature subset is also used by the Ridge residual branch.

Several scaled-distance features are inspired by blast-scaling concepts. Because the dataset does not provide an exact explosive-mass equivalent, these features are used as machine-learning proxies rather than exact physical blast calculations.

## Model Development

Three fundamentally different baseline model types were evaluated:

- **Ridge Regression** — regularised linear baseline
- **Random Forest** — nonlinear tree-based baseline
- **Neural Network** — nonlinear MLP regression model

These models provide progressively more flexible representations of the relationships between BLEVE conditions, obstacle geometry, sensor position, and resulting pressure.

The final solution uses a multi-branch ensemble.

## Final Ensemble

The final model combines four complementary prediction branches:

1. **Box-Cox MLP branch**  
   Neural networks are trained on a Box-Cox transformed target to reduce skew and improve optimisation stability.

2. **Residual Ridge + MLP branch**  
   A Ridge model first learns a broad physics-focused trend, while neural networks learn the remaining nonlinear prediction error.

3. **Log-target MLP branch**  
   Additional neural networks are trained using logarithmic target pressure to provide another representation of the strongly right-skewed target.

4. **Histogram Gradient Boosting branch**  
   A tree-based boosting model captures additional nonlinear thresholds and feature interactions.

Predictions from these branches are combined using tuned blend weights. Multiple random seeds are averaged across several model branches to reduce sensitivity to individual model initialisation.

A final validation-based calibration stage applies small corrections for systematic prediction bias.

## Event-Based Validation

Randomly splitting individual sensor rows would create a risk of information leakage because measurements from the same BLEVE event could appear in both the training and validation sets.

For example:

```text
Training:
Event 10 → Sensors 1–20

Validation:
Event 10 → Sensors 21–27
```

The model would already have seen most of the physical conditions associated with the validation observations.

Instead, this project holds out **complete BLEVE events**:

```text
Training:
Complete BLEVE events

Validation:
Different complete BLEVE events
```

This provides a more realistic estimate of performance on previously unseen BLEVE scenarios.

## Reproducibility

The required Python dependencies are listed in `requirements.txt`.

Install them with:

```bash
pip install -r requirements.txt
```

The notebook expects the following files to be available locally:

```text
train.csv
test.csv
```

They can be placed in the notebook's working directory or the `TRAIN_PATH` and `TEST_PATH` variables can be updated to point to their locations.

Run `notebooks/bleve_pressure_prediction.ipynb` from top to bottom using Jupyter Notebook, JupyterLab, or Google Colab.

The completed workflow generates:

```text
prediction.csv
```

with the columns:

```text
ID
Target Pressure (bar)
```

## Limitations and Future Work

The current evaluation uses a single event-based hold-out validation split. A stronger future evaluation could use **event-based k-fold cross-validation** to evaluate the model across several different groups of unseen BLEVE events.

Additional model families such as XGBoost, LightGBM, or CatBoost could also be evaluated using the same grouped-validation methodology.

Other possible extensions include:

- alternative calibration strategies
- feature-selection methods
- model interpretability
- prediction-error analysis by sensor location
- robustness analysis across different BLEVE physical conditions
